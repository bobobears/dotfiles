# 个股财报解读配方（本机 A 股自选股）

用户是长线 ETF + 个股量化并存的持股者。财报季（4/8/10 月）会直接问「XX 出财报了吗/解读一下」，或在持有个股大跌时问持仓决策。

## 1. 取数（东财数据中心 API，不用爬公告页）

```bash
curl -sL -A "Mozilla/5.0" -H "Referer: https://data.eastmoney.com/" \
  "https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_LICO_FN_CPD\
&columns=ALL&filter=(SECURITY_CODE%3D%22002039%22)&pageSize=40&pageNumber=1&source=WEB&client=WEB"
```

返回 `result.data`，每条一个报告期，关键字段：

| 字段 | 含义 |
|:-----|:-----|
| `REPORTDATE` | 报告期（如 `2026-09-30`） |
| `UPDATE_DATE` | 数据更新日（判断是否已含最新季报） |
| `TOTAL_OPERATE_INCOME` | 营业总收入（元） |
| `PARENT_NETPROFIT` | 归母净利（元） |
| `YSTZ` / `SJLTZ` | 营收同比% / 净利同比% |
| `BASIC_EPS` / `WEIGHTAVG_ROE` | EPS / 加权 ROE |

**坑**：
- 加 `sortColumns=REPORT_DATE` 会报 `{"code":9501,"message":"REPORT_DATE排序列不存在"}`（真实列名是 `REPORTDATE`，无下划线）。**要么删掉排序参数，要么用 `sortColumns=REPORTDATE`**；拿回来自己按日期排最稳。
- `datacenter.eastmoney.com` 与 `datacenter-web.eastmoney.com` 两个域名都能用，前者偶尔 DNS 失败就换后者。
- 同一报告期可能出现两行（本年 + 上年同期），用 `REPORTDATE[:10]` 建字典去重。
- 三季报公布日通常在 10 月下旬**盘后**（17 点后），当天盘中跌幅是「财报前」，真正的反应在次日。回答时先说明这一点，否则用户会把盘中走势当成财报反应。
- 想看上年年报基数（算 Q4、看高基数），同一接口 `pageSize=40` 就带回来 `12-31` 的行，无需另调。
- **查财报日程**（用户问「什么时候出财报」/「要不要等到财报再卖」）：用预约披露接口，`ACTUAL_PUBLISH_DATE` 为 `null` 即尚未披露：
  ```bash
  curl -sL -A "Mozilla/5.0" -H "Referer: https://data.eastmoney.com/" \
    "https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_PUBLIC_BS_APPOIN\
  &columns=SECURITY_CODE,SECURITY_NAME_ABBR,REPORT_DATE,APPOINT_PUBLISH_DATE,ACTUAL_PUBLISH_DATE\
  &filter=(SECURITY_CODE%3D%22002966%22)&pageSize=5&source=WEB&client=WEB"
  ```
  手上有确切日期，「止盈/持有」才能落到「先减一半、剩下过财报再定」这种可执行形态，而不是空谈位置高低。
- **取数失败先判性质**：东财 datacenter/push2 连续多次调用后可能返回 `HTTP:000` 或空体（**限流，不是 DNS**，别去改 hosts），停几秒或换 `datacenter.eastmoney.com` / `datacenter-web` 另一域名重试；仍不行就改走新浪/腾讯取行情，但**财报三大表数据没有等价替代源**，必须把这一点告诉用户而不是编数字。

## 2. 必须拆单季 —— 累计数会骗人

**这是最容易漏的一步**。累计同比为正、单季大幅负增长是常见组合（也可能反过来）。

```python
Q3_rev = 三季报营收 - 中报营收
Q3_np  = 三季报净利 - 中报净利
Q3同比 = Q3_本年 / Q3_去年 - 1
```

输出必须同时给：**前三季累计（+同比）** 与 **最新单季（+同比）**，以及两者的背离。用户关心的是「最近这个季度发生了什么」。

再看 **单季净利率**（`Q3净利/Q3营收`）和 **该季占前三季利润比重** —— 水电、火电、白电等季节性行业，单季占比可能高达 70%，那这一季塌了全年就定性了。

## 3. 归因：先分「周期性/气候」与「经营性」

不要把单季下滑直接当「经营恶化」。按行业查对应驱动：

- **水电**：业绩 ≈ 来水量 × 装机。看公告里的「来水量同比」和「发电量同比」，**且必须分流域看**。总来水偏多而发电量下降是真实存在的（大水在小流域、主力水库所在流域来水偏少），这是气候不是经营。同时必须报分电厂发电量（董箐/光照/马马崖等主力厂 vs 小厂）。
- **光伏/风电**：看利用小时数 + 上网电价；毛利率断崖（如跌到个位数）要单独点出来，通常是新并网项目折旧摊薄。
- **火电**：煤价 + 电价 + 利用小时。
- **制造业**：量、价、毛利率拆开看，营收涨而利润不涨＝价格战或成本上涨。

**高基数陷阱**：行业周期股/气候股的单年利润可能是十年极值（丰水年、涨价年）。必须拉 10 年净利序列给用户看，指出「去年是极值不是常态」，再算当年是否仍好于历史中位。忽略这一点会得出完全相反的结论。

## 4. 估值是否还撑得住

用「现价 × 总股本（≈ 归母净利/EPS）」算市值，除以当年净利预估（前三季 + Q4 历史同期比推）。给出 PE 区间，并对照同业中枢（水电约 15–20 倍、银行 5–7 倍）说明是贵还是便宜。**结论要落到「估值没崩但也没便宜到能扛住更差预期」这类可操作判断，不要只报数字。**

## 5. 「业绩杀」vs「情绪杀」——决定后续动作的关键区分

| | 情绪杀 | 业绩杀 |
|:--|:--|:--|
| 触发 | 大盘/板块普跌、消息面 | 财报证实基本面下修 |
| 反弹 | 容易 V 型修复 | 要等下一个业绩拐点才修复 |
| 应对 | 可持有/等反弹 | **反抽就是离场窗口，不是加仓机会** |

判定为业绩杀后，明确告诉用户「反抽该走」而不是「等反弹回本」。

## 6. 纪律优先于预测

用户常自己给出过止损位/减仓位（如成本价、MA20）。一旦盘中跌破，**直接引用他自己定的价位执行，不要用"再等等"软化**：

1. 先报破位事实（现价、跌幅、是否放量、创多少日新低、六条均线状态）
2. 摆出下一支撑位和到那里的下跌空间（换算成百分比）
3. 做风险收益对比（现在走亏 X%，死扛到下一支撑亏 Y%）
4. 给一个主推动作 + 一个折中动作 + 一个明确禁止项（补仓摊平/死扛等回本）

放量破位 + 全部均线跌破 + 业绩杀 三条同时成立时，不要留「观察看看」的模糊选项。

## 7. 输出格式

- 表格给数据（累计/单季对照、均线状态、支撑位）
- 「一句话结论」放在最后，加粗，可直接转述
- 结尾固定加「基于公司公告与公开数据的分析，不构成投资建议」
