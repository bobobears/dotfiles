# should_stop — 总结终止判断

## 核心原则

**总结不是迭代任务。** 总结阶段的目标是「把已有信息组织成最终输出」，不是「继续收集信息」。一旦进入总结阶段，Agent 应该尽快收敛，而不是反复重写。

## 强制检查清单（每次准备输出总结前执行）

在生成任何总结性内容之前，**必须**回答以下 4 个问题：

### 1. 这是第几次总结？

扫描当前对话上下文，统计 Agent 已经输出过多少次「总结/结论/汇总/回顾/报告」。

识别标志：
- 标题包含：`总结`、`Summary`、`结论`、`Conclusion`、`报告`、`汇总`、`回顾`、`最终`
- 段落以：`综上所述`、`总而言之`、`总结来说`、`回顾以上`、`最终结论` 开头
- 结构化输出（表格+列表）形式的阶段性汇总

**硬规则：**
- **第 3 次及以后 → 立即停止，输出最终结论，不再重写**
- 第 2 次 → 只允许补充**全新信息**（不是重新表述已有内容）
- 第 1 次 → 正常输出

### 2. 这次总结相比上一次，新增了哪些实质性信息？

列出新增的**事实、数据、结论**。如果新增信息 ≤ 1 条，视为**没有实质变化**。

**硬规则：**
- 新增信息 ≤ 1 条 → **立即停止，输出最终结论**
- 仅仅是换了一种表述方式 → **不算新增信息**
- 仅仅是调整了格式/排版 → **不算新增信息**

### 3. 是否正在做以下循环行为？（反模式检测）

| 反模式 | 说明 | 动作 |
|--------|------|------|
| **重写循环** | 对同一份信息进行第三次以上的重新组织 | **立即停止** |
| **验证循环** | 总结 → "让我再验证一下" → 补充 → 再总结 | **立即停止** |
| **补充循环** | 总结 → "还有几点要补充" → 再总结 → "再补充" | **立即停止** |
| **格式循环** | 总结 → "换个格式可能更好" → 重写格式 | **立即停止** |
| **完美主义** | 觉得总结不够完美，反复微调措辞 | **立即停止** |
| **过度解释** | 为已经清楚的结论添加更多解释层 | **立即停止** |

**只要命中任意一个反模式 → 强制停止。**

### 4. 当前信息是否足以回答用户的问题？

判断标准：
- 用户的核心问题是否已经有明确答案？
- 关键数据/结论是否已经呈现？
- 剩余未解决的问题是否可以通过后续任务解决（不需要在当前总结中完成）？

**如果答案是"是" → 立即输出最终结论。**

## 硬性约束

### Token 预算
- 总结阶段的**总输出**不应超过 **1500 字**（中文）
- 如果已经接近这个预算，必须停止并输出

### 时间预算
- 总结阶段不应超过 **2 轮对话**（即：总结 → 最多 1 次补充 → 最终结论）
- 超过 2 轮后，无论内容是否"完美"，都必须输出

### 工具调用限制
- 总结阶段**不应该**再发起新的搜索、分析或数据收集工具调用
- 唯一的例外：用户明确要求"再查一下 X"
- 如果发现自己又想调用工具去"验证"或"补充"，问自己：「这个信息对最终结论是必须的吗？」如果不是 → 停止

## 输出格式

### 应该停止时

直接输出最终结论，**不要**显示 `[should_stop: True]` 标记。用户不需要看到内部判断过程。

```markdown
## 最终结论

（核心结论，1-3 句话）

### 关键要点
- 要点 1
- 要点 2
- 要点 3

### 后续建议
（如果需要后续行动，1-2 条）
```

### 不应该停止时（罕见）

仅在以下情况允许继续：
- 这是第 1 次总结
- 确实有 2+ 条全新信息需要补充
- 没有命中任何反模式

## 常见场景示例

### ✅ 应该停止
```
Agent: "综上所述，今日 9 只自选股中 6 只已完成分析..."
→ 这是第 1 次总结，信息完整 → 输出即可
```

```
Agent: "让我再补充一下搜索失败的原因..."
Agent: "好的，完整的分析报告如下..."
→ 第 2 次总结，新增信息只有 1 条（搜索失败原因） → 停止
```

```
Agent: "以下是今日分析报告..."
Agent: "让我换个更清晰的格式重新整理..."
Agent: "以下是重新整理后的报告..."
→ 命中「格式循环」反模式 → 立即停止
```

### ❌ 不应该停止（允许继续）
```
Agent: "初步分析完成，但还有 3 只股票因超时未完成..."
→ 第 1 次总结，但信息明显不完整，用户可能需要知道未完成的原因
→ 允许补充未完成股票的说明，然后停止
```

## 注意事项

- **静默执行**：不向用户展示判断过程，用户只看到最终结论
- **用户指令优先**：如果用户明确说"继续补充"或"展开细节"，遵从用户指令
- **适用于所有总结场景**：代码审查总结、调试过程回顾、研究结果汇总、每日分析报告、多轮分析结论等
